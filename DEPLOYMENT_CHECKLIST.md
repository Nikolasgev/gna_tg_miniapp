## 🔴 Что обязательно сделать перед запуском

### 1. Безопасность Backend

#### 1.1. Настроить секретные ключи

- [ ] **Создать SECRET_KEY** - это как пароль для вашего приложения
  ```bash
  python -c "import secrets; print(secrets.token_urlsafe(32))"
  ```
  Скопируйте полученный ключ и сохраните его. Он понадобится для настройки на хостинге.
  z-1kng8zVNcng3sHDL8fJ3MP8WiRI0iwtIfm7gJTJJc

- [ ] **Установить пароль для админки (ADMIN_PASSWORD)**
  - Придумайте надежный пароль (минимум 8 символов, с буквами и цифрами)
  - Этот пароль будет использоваться для входа в админ-панель
  - Сохраните его в безопасном месте - он понадобится для входа
  - Добавьте его в настройки хостинга как переменную окружения `ADMIN_PASSWORD`

- [ ] **Настроить CORS** - указать, какие сайты могут обращаться к вашему backend
  - Укажите только реальные адреса вашего мини-приложения и админ-панели
  - Не разрешайте всем сайтам (`*`) - это небезопасно
  - Это настраивается в переменных окружения на хостинге как `CORS_ORIGINS`

#### 1.2. Защита админских страниц

- [x] **Добавлена проверка пароля для админских функций**
  - ✅ Список заказов (`GET /{business_slug}/orders`)
  - ✅ Изменение статуса заказа (`PATCH /orders/{order_id}/status`)
  - ✅ Отмена заказа (`POST /orders/{order_id}/cancel`)
  - ✅ Все функции требуют JWT токен, полученный через `/api/v1/admin/auth/login`
  
  **Как это работает:**
  1. Админ входит через `/api/v1/admin/auth/login` с паролем
  2. Получает JWT токен
  3. Использует токен в заголовке `Authorization: Bearer <токен>` для доступа к админским функциям

### 2. База данных и Redis на том же хостинге

**Рекомендуется: Railway** - позволяет разместить backend, PostgreSQL и Redis в одном проекте.

- [ ] **Создать проект на Railway**
  1. Зайдите на https://railway.app/
  2. Создайте аккаунт через GitHub
  3. Создайте новый проект

- [ ] **Добавить PostgreSQL базу данных**
  1. В проекте Railway нажмите "New" → "Database" → "PostgreSQL"
  2. Railway автоматически создаст базу данных
  3. В настройках базы найдите "Connect" → скопируйте "Postgres Connection URL"
  4. Это будет ваш `DATABASE_URL`

- [ ] **Добавить Redis**
  1. В том же проекте Railway нажмите "New" → "Database" → "Redis"
  2. Railway автоматически создаст Redis
  3. В настройках Redis найдите "Connect" → скопируйте URL
  4. Это будет ваш `REDIS_URL`

- [ ] **Применить миграции** - создать все нужные таблицы в базе
  ```bash
  # Через Railway CLI
  railway login
  railway link  # выберите ваш проект
  railway run alembic upgrade head
  ```
  Или через Railway Dashboard → ваш сервис → Deployments → View Logs → выполните команду

- [ ] **Настроить переменные окружения**
  - Railway автоматически создаст переменные `DATABASE_URL` и `REDIS_URL` для вашего backend сервиса
  - Они будут доступны автоматически, когда вы добавите backend сервис в тот же проект

### 4. Развертывание Backend на Railway

- [ ] **Добавить backend сервис в проект Railway**
  1. В том же проекте Railway (где уже есть PostgreSQL и Redis) нажмите "New"
  2. Выберите "GitHub Repo"
  3. Выберите ваш репозиторий
  4. Railway спросит "Which directory?" → укажите `backend`
  5. Railway автоматически обнаружит Dockerfile и начнет деплой

- [ ] **Проверить Dockerfile**
  - Убедиться, что файл `backend/Dockerfile` готов для production
  - В production не должен использоваться режим `--reload` (автоперезагрузка)

- [ ] **Настроить переменные окружения в Railway**
  1. Откройте ваш backend сервис в Railway
  2. Перейдите в "Settings" → "Variables"
  3. Добавьте следующие переменные:
     ```bash
     SECRET_KEY=<ваш_сгенерированный_ключ>  # Ключ из шага 1.1
     ADMIN_PASSWORD=<ваш_пароль>            # Пароль для админки
     ENVIRONMENT=production                  # Режим работы
     CORS_ORIGINS=["https://ваш-сайт.com","https://админ.ваш-сайт.com"]  # Разрешенные сайты
     ```
  
  **Важно:** `DATABASE_URL` и `REDIS_URL` Railway добавит автоматически, если PostgreSQL и Redis находятся в том же проекте!

- [ ] **Проверить, что backend работает**
  - Откройте `https://ваш-backend-url.com/health`
  - Должно вернуться `{"status": "ok"}`

- [ ] **Настроить хранение файлов (изображений товаров)**
  - Убедиться, что папка `uploads/images` создается автоматически
  - Можно хранить локально или в облаке (S3, Cloudinary)

### 5. Развертывание Frontend

#### 5.1. Мини-приложение (Telegram Mini App)

- [ ] **Собрать приложение для production**
  ```bash
  cd frontend
  flutter build web --release --dart-define=API_BASE_URL=https://ваш-backend-url.com --dart-define=ENVIRONMENT=production
  ```
  Замените `ваш-backend-url.com` на реальный адрес вашего backend.

- [ ] **Указать адрес backend**
  - В команде сборки через `--dart-define=API_BASE_URL=...`
  - Или в файле `frontend/lib/core/config/environment.dart`

- [ ] **Разместить на хостинге**
  - Можно использовать Netlify, Vercel, GitHub Pages или любой другой статический хостинг
  - Убедиться, что CORS на backend разрешает этот домен

#### 5.2. Админ-панель

- [ ] **Собрать админ-панель для production**
  ```bash
  cd frontend
  flutter build web --release --target lib/admin_panel/main.dart --dart-define=API_BASE_URL=https://ваш-backend-url.com --dart-define=ENVIRONMENT=production
  ```

- [ ] **Разместить на хостинге**
  - Можно на отдельном домене или поддомене
  - Убедиться, что CORS на backend разрешает этот домен

## 📝 Пример настроек для production

Вот что нужно добавить в переменные окружения на хостинге:

```bash
# База данных
DATABASE_URL=postgresql+asyncpg://логин:пароль@хост:5432/имя_базы

# Redis
REDIS_URL=redis://хост:6379/0

# Безопасность
SECRET_KEY=<сгенерированный_ключ_32_символа>  # Из шага 1.1
ADMIN_PASSWORD=<надежный_пароль>              # Ваш пароль для админки

# Режим работы
ENVIRONMENT=production

# Разрешенные сайты (JSON массив)
CORS_ORIGINS=["https://ваш-мини-приложение.com","https://ваша-админка.com"]

# Telegram (опционально, если нужны уведомления)
TELEGRAM_BOT_TOKEN=<токен_бота>

# Платежи (опционально, если нужны реальные платежи)
YOOKASSA_SHOP_ID=<id_магазина>
YOOKASSA_SECRET_KEY=<секретный_ключ>
YOOKASSA_WEBHOOK_SECRET=<секрет_для_webhook>

# Мониторинг (опционально)
SENTRY_DSN=<адрес_для_sentry>
```
