# Стратегия Git: корень и вложенные `backend/` / `frontend/`

## Проблема

Если в каталогах `backend/` или `frontend/` есть собственная папка `.git`, Git в корне репозитория **не отслеживает** файлы внутри них как обычные файлы — видит только «gitlink» или пустую ссылку, пока не настроены submodule.

## Рекомендуемый вариант: один монорепозиторий

Подходит, если один продукт и одна команда.

1. Сохраните резервные копии веток вложенных репозиториев (на всякий случай):
   ```bash
   cd backend && git remote -v && git branch -a
   cd ../frontend && git remote -v && git branch -a
   ```
2. В корне репозитория:
   ```bash
   rm -rf backend/.git frontend/.git
   git add backend frontend
   git status   # убедитесь, что видны все нужные файлы
   git commit -m "chore: включить backend и frontend в корневой репозиторий"
   ```
3. При необходимости перенесите старые remote как отдельные зеркала или архивные репозитории.

## Альтернатива: Git submodules

Подходит, если backend и frontend живут отдельными релизами и разными правами доступа.

1. Удалите вложенные каталоги из индекса корня (если они были добавлены неправильно).
2. Добавьте submodule:
   ```bash
   git submodule add <url-backend> backend
   git submodule add <url-frontend> frontend
   git submodule update --init --recursive
   ```
3. Клонирование: `git clone --recurse-submodules <root-url>`.

## Что выбрать

| Критерий | Один репо | Submodule |
|----------|-----------|-----------|
| Простота CI/CD | Да | Сложнее |
| Независимые релизы | Нет | Да |
| Один PR на фичу сквозь стек | Да | Неудобно |

**Текущая рекомендация проекта:** один монорепозиторий после миграции по шагам выше.
